# 実機と公開コードの検証範囲

## 実機で成功した試作版

2026-10-02、i770R / `AQUA770R 2A 0006` / Apple Silicon macOS / BLEで実施しました。機器名・シリアル番号・個人情報・生メモリ・APK・バグレポートは公開していません。

1. 変更前の低位メモリを読み、HISTORYの位置と本体表示の対応を確認した。
2. バックアップと現在値を照合した。
3. HISTORYを元と同じ値でB2送信した。ACK=5A、低位256バイトの差分=0だった。
4. 内部状態候補2ブロックを退避した。
5. HISTORYの16バイトだけを0でB2送信した。ACK=5Aだった。
6. 同じ接続で読み直した。TOTAL DIVE=0、HISTORYの全16バイト=0。変更はHISTORY内の9バイトのみだった。
7. 校正候補48バイト、内部状態候補2×256バイトを比較し、完全一致を確認した。
8. 切断・再接続後もHISTORYの全16バイト=0だった。所有者が本体表示も確認した。

匿名化した結果は[evidence/hardware-reset-2026-10-02.json](../evidence/hardware-reset-2026-10-02.json)です。原本の再現に必要な機器固有データを含めていないため、公開JSONは生メモリの代わりにはなりません。

## ログ消去の試行

HISTORYの0化とは別に、ログ本文606ページのFF化を試しました。全ページのACKと読み直しは成功しましたが、元の索引が残ったため本体の選択枠も残りました。

この時点で「8→7→…→1→99→98…」という表示が報告されました。番号の並びだけで順序破損と判断することはできません。しかし本文のFF化がログ0件表示を達成しなかったことは確認しています。

そのため606ページを消去前のバックアップへ復元し、606/606のACKと完全一致を確認しました。HISTORY=0、校正候補、MY INFO、内部状態候補も維持しました。以降はログ本文を再消去していません。

管理ページ4の変更は、通常の接続、公式の復元用開始手順82、フレーム長やATT方式の変更でも成功しませんでした。応答なしの原因は未確定です。「保護が解除できない」「EEPROMが壊れている」とは断定していません。最後の全体再検証は、再接続失敗と電波不検出により完了していません。

## 公開CLIの自動検証

公開用CLIは成功した試作版から構成を整理したものです。公開のために実機のHISTORYを再度変更していません。

リスクは高：不揮発メモリを書き換えるため、バックアップ・変更範囲の固定・異常時の停止を受入条件にしました。外部境界であるGATTだけを模擬し、実際のCLIの送受信・チェックサム・保存・照合処理を通して検証します。

| 受入条件 | 確認方法 |
|---|---|
| 完全なB2と20/8バイトのフレーム | 観測形式に基づく固定バイト列 |
| 誤機器・未確認バージョンは停止 | GATT契約テスト |
| デフォルトのinspectでメモリを書かない | GATT契約テスト |
| バックアップを上書きしない | 実ファイルシステムでのテスト |
| 同値試験と読み直しを経てから0化 | GATT契約テスト |
| HISTORY以外と内部状態候補を維持 | 前後の全対象バイト比較 |
| NAK・ACK欠落・チェックサム不一致で停止 | GATT契約テスト、自動再送0回の確認 |
| ACKだけでは成功にしない | 書き込みを反映しない模擬機器でのテスト |
| HISTORYだけを復元し、新しい状態を上書きしない | 改ざん・別機器・新しいHISTORYの拒否テスト |
| 書き込みコマンドには明示的なフラグが必要 | CLI引数テスト |

独立した別レビュアーによる確認、公開CLIの実機テスト、水中テスト、別OS・別ファームウェアのテストは未実施です。自動テストはこれらの代わりにはなりません。

## 復旧

保存済みバックアップからHISTORYだけを戻すコマンドを用意しました。全メモリの復元ではなく、校正や内部状態候補の書き戻しも行いません。新しい潜水などで状態が変わった後には復元を拒否します。

応答がない書き込みは、実際に保存されたか不明です。その場合は切断して状態を確認し、同じ書き込みを自動的に繰り返しません。端末のfailuresやbyte比較の不一致を消して「成功扱い」にする処理もありません。
