# ログ番号と記録の順序

復元したデータでは、99件の記録が重複なく新しい順に並んでいました。記録の順序に異常は検出していません。ただし、本体画面の番号が正常かどうかは未確認です。

調査中、本体のログ番号が`8 → 7 → … → 1 → 99 → 98 … → 9`の順に表示されるという報告がありました。この並びだけでは、記録の時系列が乱れたとは判断できません。以下は、確認できたデータの順序と未確認の表示規則についての説明です。

## マニュアルの説明

[公式マニュアル](https://files.plytix.com/api/v1.1/file/public_files/pim/assets/0b/ab/e6/61/61e6ab0b426259d4c914e07f/texts/0c/8e/36/64/64368e0c02b279dd763d3b98/i770R_owners_manual_EN.pdf)のLOGの説明は印刷ページ24にあります。本体で表示するログは最大99件で、新しい記録によって古い記録が置き換わります。ログ選択画面（LOG ENTRY FINDER）のENTRY欄と、各操作期間のDIVE番号は別の表示です。

ただし、ENTRY番号が必ず99から1へ戻るという規則までは確認できませんでした。`206 % 99 = 8`という計算が合うだけでは、累計206本と表示番号8の関係を仕様とは断定できません。

## 保存データから確認した順序

表示用の保存領域には、1枠64バイトの記録が100枠ありました。ダウンロード用の206件と照合した結果、100枠全てが直近100件に対応しています。

元の索引にある開始位置と終了位置を使い、最新の記録から64バイトずつ遡りました。保存領域の先頭より前に進んだ場合は、末尾に戻って続きを読みます。

この方法で参照する表示対象は99件でした。ダウンロード記録の番号は205、204、…、107と1つずつ減り、重複は0件でした。この番号は解析用に0から付けたもので、本体画面のENTRY番号とは別です。

消去を試したログ本文606ページは、元のバックアップから復元し、完全一致を確認しました。HISTORYは0のまま維持しています。

以上の確認では、復元した索引が参照する記録の順序に異常は検出していません。保存位置が途中で末尾に戻っても、それだけで記録の時系列が変わるわけではありません。

## 未確認の表示と動作

本体画面の日付・時刻が保存データと一致するか、ENTRY番号をどう付けるかは未確認です。次の潜水に何番が付くかも確認していません。最後のBluetooth接続に失敗したため、本体に表示される全ログを再ダウンロードして検証する作業は完了していません。

HISTORYは0でも、古いログは残っています。ログが0件の工場出荷時の状態には戻っていません。表示番号の並びだけから、潜水計算の正しさを判断することもできません。
