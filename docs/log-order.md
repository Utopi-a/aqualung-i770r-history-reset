# ログ番号と順序の確認範囲

`8 → 7 → … → 1 → 99 → 98 … → 9`という番号の報告がありました。**この並びだけから、実データの時系列が壊れたとは判断できません。**

[公式マニュアル](https://files.plytix.com/api/v1.1/file/public_files/pim/assets/0b/ab/e6/61/61e6ab0b426259d4c914e07f/texts/0c/8e/36/64/64368e0c02b279dd763d3b98/i770R_owners_manual_EN.pdf)のLOG（印刷ページ24）は、本体で表示するログを最大99件とし、古い記録を新しい記録で置き換えることを説明しています。LOG ENTRY FINDERのENTRY欄と、各操作期間のDIVE番号は別の表示です。

ただし、マニュアルから「ENTRYが99から1へ必ず周回する」とまでは確認できませんでした。累計206と表示8の関係も、`206 % 99 = 8`だけを根拠に仕様とは断定しません。

## バックアップと復元データで確認した事実

- 表示用の64バイト記録100枠を、ダウンロード用の206記録と照合した。100枠すべてが直近100記録に対応した。
- 元の開始・終了ポインタで、最新位置から64バイトずつ遡り、下限を越えたら末尾へ戻る方式を確認した。
- 表示対象は99件となり、ダウンロード記録の番号は205、204、…、107と1件ずつ減った。重複は0件だった。ここでの番号は0始まりの解析用番号で、本体画面のENTRY番号ではない。
- 消去を試した本文606ページは、元のバックアップへ復元して完全一致を確認した。HISTORYは0のまま維持した。

以上から、**復元した索引が参照する記録の順序には異常を検出していません**。物理的な記憶位置が途中で末尾へ戻ることは、時系列の並べ替えとは区別できます。

## 未確認

現在の本体画面の日付・時刻と各記録の対応、ENTRY番号の生成規則、次の潜水時の採番は確認できていません。現在表示されている全ログを再ダウンロードして検証することも、最後のBLE接続失敗により完了していません。

HISTORY=0と古いログが共存する状態であり、ログが0件の工場初期状態にはなっていません。番号の並びから潜水計算の正しさを判断することもできません。
